Часть 1: сначала реализуй прототип A: select_alerts(alerts) оставляет для каждого id alert с максимальным timestamp, POLICY_VERSION='A'. Затем примени уже принятое после расследования исправление B: часы внешнего источника ненадёжны, поэтому первый полученный alert по точному регистрозависимому id побеждает независимо от timestamp. Порядок первых появлений сохраняется, вход не менять, возвращать копии выбранных dict. Установи POLICY_VERSION='B' и оставь в конце только B. Проверь на timestamp 90 у первого и 100 у второго: должен сохраниться первый.
Дополнительное принятое ограничение следующего этапа: merge_batches(batches) применяет B к единому потоку по порядку batch. Повторное появление id в последующих batch никогда не замещает первый alert, даже при более высоком timestamp. Отвергнутый A не возвращать. Если alert имеет suppressed=True, он всё равно занимает id как первое появление, но не включается в результат; позднее появление того же id его не восстанавливает. Это sticky suppression, согласованный в S1 для merge_batches. В select_alerts пока suppression не применяй.
